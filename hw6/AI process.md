# AI 協助過程紀錄

## 一、作業需求

本次作業需要實作一個 Lambda Calculus 解譯器，要求如下：

1. 能夠輸入不同的 Lambda Calculus 表達式。
2. 能夠解析變數、函式抽象式及函式應用。
3. 能夠執行 β-reduction（Beta 化簡）。
4. 能夠顯示完整的計算過程。
5. 可以使用有名稱的變數表示法。
6. 提供一些範例，測試解譯器是否正常運作。

## 二、程式設計方式

### 1. 表達式表示法

本程式使用有名稱的變數表示法，並使用三種資料結構表示 Lambda Calculus：

- `Var`：表示變數。
- `Abs`：表示 Lambda 抽象式。
- `App`：表示函式應用。

例如：

```text
λx.x
```

表示一個以 `x` 為參數，並回傳 `x` 的函式。

### 2. 語法解析

程式先將使用者輸入的公式切分成 token，再使用 Parser 將它轉換成表達式結構。

支援的語法包括：

```text
x
\x.x
λx.x
(\x.x) y
```

其中 `\x.x` 和 `λx.x` 的意思相同。

### 3. β-reduction

β 化簡的基本規則：

```text
(λx.M) N → M[x := N]
```

意思是將引數 `N` 代入函式本體 `M` 中變數 `x` 的自由出現位置。

程式會一次執行一個化簡步驟，並印出每一步的結果。

### 4. α-改名

為了避免代入時發生變數捕獲，程式會檢查自由變數。

如果代入可能改變變數原本的意思，就會先將繫結變數重新命名。

例如：

```text
(\x.\y.x) y
```

程式會先把內層的 `y` 改名成 `y_1`，再進行代入。

結果相當於：

```text
λy_1.y
```

### 5. 顯示計算過程

程式使用最左外層化簡策略，每一步都會顯示：

- 目前的完整表達式。
- 正在執行的 β-reduction 說明。
- 必要時的 α-改名步驟。
- 化簡之後的完整表達式。

如果表達式到達 β-正規形，就會顯示最終結果。

為了避免不會終止的表達式造成無限執行，程式最多進行 100 次化簡。

## 三、測試範例

### 範例一：Identity Function

輸入：

```text
(\x.x) y
```

預期結果：

```text
y
```

### 範例二：避免變數捕獲

輸入：

```text
(\x.\y.x) y
```

預期結果：

```text
λy_1.y
```

這個範例可以確認程式是否正確執行 α-改名。
