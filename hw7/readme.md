# 第七週習題：動態規劃與文字算法 — LCS

## 一、問題選擇

本作業選擇「最長共同子序列」（Longest Common Subsequence，LCS）作為文字類型的問題。

給定兩段文字 A 和 B，要找出一個最長的字元序列，使它同時是 A 和 B 的子序列。子序列不要求字元連續，但字元的相對順序必須一致。LCS 是文字差異比對（diff）常見的基礎概念。

例如：

```text
A = ABCBDAB
B = BDCABA
```

其中一個最長共同子序列是：

```text
BCBA
```

LCS 可能不只一種，因此不同實作回傳不同但同樣長度的結果也是合理的。

## 二、方法一：非動態規劃（直接遞迴）

程式使用 `lcs_recursive(a, b)`，依照以下規則處理：

1. 如果其中一段文字為空字串，LCS 就是空字串。
2. 如果兩段文字的最後一個字元相同，該字元可以接在子問題的 LCS 後面。
3. 如果最後一個字元不同，就分別移除 A 的最後一個字元、或 B 的最後一個字元，遞迴求出兩個結果，再選擇較長的結果。

概念如下：

```text
若 A 最後字元 == B 最後字元：
    LCS(A, B) = LCS(A去掉最後字元, B去掉最後字元) + 最後字元

否則：
    比較 LCS(A去掉最後字元, B)
    與 LCS(A, B去掉最後字元)
    取較長的結果
```

### 優點

- 程式結構直觀，容易依照定義實作。
- 不需要建立 DP 表格。

### 缺點

當最後字元不同時，程式會展開兩個分支，而且可能反覆計算相同的子問題，因此遞迴呼叫數量會快速增加。

### 複雜度

令兩段文字長度分別為 `m` 與 `n`。

- **時間複雜度：** 指數級，常用上界表示為 `O(2^(m+n))`。
- **空間複雜度：** 約 `O(m+n)` 的遞迴堆疊；字串切片和結果字串也會產生額外成本。

本程式對純遞迴版本設定呼叫次數和輸入長度限制，以免長文字造成過長的執行時間。

## 三、方法二：動態規劃（Dynamic Programming）

程式使用 `lcs_dynamic_programming(a, b)`，建立一個二維表格 `dp`。

`dp[i][j]` 表示 A 的前 `i` 個字元與 B 的前 `j` 個字元之間的 LCS 長度。

### 狀態轉移

如果兩個目前字元相同：

```text
dp[i][j] = dp[i-1][j-1] + 1
```

如果兩個字元不同：

```text
dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

初始條件為：

```text
dp[0][j] = 0
dp[i][0] = 0
```

因為空字串和任何字串的 LCS 都是空字串。

### 如何還原 LCS？

表格填完後，從 `dp[m][n]` 開始回溯：

1. 如果 A 和 B 的目前字元相同，把字元加入答案，並往左上移動。
2. 如果不同，就往表格中數值較大的方向移動。
3. 最後把收集的字元反轉，即可得到一個 LCS。

### 複雜度

- **時間複雜度：** `O(m*n)`。
- **空間複雜度：** `O(m*n)`。

因為表格有 `(m+1) × (n+1)` 個狀態，每個狀態只做固定數量的計算。

---

## 四、兩種方法比較

| 比較項目 | 非動態規劃：直接遞迴 | 動態規劃：DP 表格 |
|---|---|---|
| 核心想法 | 依照定義遞迴拆解問題 | 儲存並重用子問題答案 |
| 重複計算 | 很多 | 同一狀態只計算一次 |
| 時間複雜度 | 指數級，上界 `O(2^(m+n))` | `O(m*n)` |
| 空間複雜度 | 約 `O(m+n)` 遞迴堆疊，另有字串成本 | `O(m*n)` |
| 長文字 | 可能非常慢 | 通常較適合 |

## 五、執行方式

需要 Python 3，不需要安裝額外套件。

```bash
python lcs_compare.py
```

執行後輸入兩段文字。直接按 Enter 使用預設範例：

```text
A = ABCBDAB
B = BDCABA
```

程式會輸出兩種演算法找到的 LCS、LCS 長度、純遞迴呼叫次數、執行時間、DP 填表狀態數，以及結果驗證。

由於純遞迴的時間複雜度是指數級，如果兩段文字合計長度超過設定值，程式會略過純遞迴測試，避免等待過久。

## 六、實驗觀察

對短字串而言，兩種方法都能找到正確的 LCS。純遞迴的優點是程式較直接，但最後字元不相同時會展開兩個子問題，因此會反覆計算。

動態規劃把子問題的答案存入表格，讓每個狀態只需填寫一次。因此對於較長的文字，動態規劃通常更有效率。

實際執行時間會受到電腦、Python 版本及系統負載影響，應以本機執行結果為準。若有多個 LCS 長度相同，兩種方法可能回傳不同字串，但仍可能都是正確答案。

## 七、結論

本作業使用 LCS 作為文字算法問題，比較直接遞迴和動態規劃兩種解法。

直接遞迴依照問題定義拆分子問題，容易理解，但是因為重複計算而有指數級時間成本。

動態規劃利用二維表格保存中間結果，把時間複雜度降低到 `O(m*n)`，更適合處理長度較大的文字。

這次實驗讓我了解，動態規劃的關鍵是找出重複子問題，並儲存已計算的結果以避免重複工作。
