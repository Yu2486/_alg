# 第8週習題：旅行推銷員問題（TSP）五種演算法比較

## 一、作業目的

旅行推銷員問題（Traveling Salesman Problem, TSP）是指：給定多個城市以及城市間的距離，找一條每個城市恰好拜訪一次，最後回到起點，而且總距離盡可能短的巡迴路線。

本作業以同一組城市資料比較五種方法：

1. 改良法：以貪婪路徑為初始解，再使用 2-opt 反覆改善。
2. 爬山演算法：隨機交換兩個城市，只接受更短的路徑。
3. 模擬退火法：使用 2-opt 產生鄰居，也可能依機率接受較差路徑。
4. 梯度下降法：使用連續鬆弛、softmax 與懲罰項來近似最佳化，再解碼為合法路徑。
5. 貪婪演算法：每次前往最近的未拜訪城市。

程式只使用 Python 標準函式庫，不需要安裝 NumPy 或 Matplotlib。

## 二、如何執行

需要 Python 3。在終端機執行：

```bash
python tsp_five_methods.py
```

程式會顯示每種方法的城市順序、封閉路徑總距離及執行時間。

## 三、測試資料

程式固定使用 20 個城市。城市座標在 0 到 100 的平面範圍內隨機產生，亂數種子設定為 `42`，因此每次執行都會使用相同的座標。

五種演算法使用同一個距離矩陣，方便比較。

兩個城市之間使用歐氏距離：

```text
distance(A, B) = sqrt((Ax - Bx)^2 + (Ay - By)^2)
```

路徑距離會包含最後一個城市回到第一個城市的距離。

## 四、五種方法的原理

### 1. 改良法：Greedy + 2-opt

先用最近鄰居法建立一條可行路徑，再使用 2-opt 改良路徑。

2-opt 會挑選路徑中的兩條邊，將中間一段的順序反轉。如果新路徑更短，就接受這次改動。程式每輪檢查所有 2-opt 選擇，並採用改善最多的一個，直到找不到可以縮短路徑的改動。

如果舊邊為 `(a,b)` 和 `(c,d)`，新邊為 `(a,c)` 和 `(b,d)`，距離變化為：

```text
Delta = d(a,c) + d(b,d) - d(a,b) - d(c,d)
```

當 `Delta < 0` 時，代表路徑變短。

**特點：** 通常能明顯改善貪婪解，但只能保證到達 2-opt 的局部最佳，不能保證全域最佳。

**複雜度：** 若改善輪數為 `R`，每輪檢查約 `O(n^2)` 個候選，因此主要成本約為 `O(R * n^2)`，另外還有每次反轉路段的成本。

### 2. 爬山演算法：Hill Climbing

隨機產生一條初始路徑，每次隨機挑選兩個城市交換位置，計算交換後的路徑距離。如果新路徑更短，就接受；否則還原交換。重複指定次數。

**特點：** 實作簡單，而且只會接受改善的路徑；但可能卡在局部最佳，不能接受較差解來離開目前的區域。因為每次只抽樣一個鄰居，也可能錯過其他更好的改動。

**複雜度：** 若執行 `I` 次，每次完整重算路徑長度需要 `O(n)`，總時間約為 `O(I * n)`；額外路徑空間約 `O(n)`。

### 3. 模擬退火法：Simulated Annealing

模擬退火法同樣反覆產生鄰居路徑，但不只接受更短的路徑。令：

```text
Delta = 新路徑距離 - 目前路徑距離
```

- 若 `Delta < 0`，新路徑比較短，直接接受。
- 若 `Delta >= 0`，以機率 `exp(-Delta / T)` 接受，其中 `T` 是目前溫度。

溫度會逐步降低。高溫時較容易接受較差解，能探索更多不同路徑；低溫時較少接受變差的解，逐漸穩定下來。

程式會另外記錄過程中找到的最佳路徑，最後回傳最佳解，而不是最後一個目前解。

**特點：** 有機會跳離局部最佳，但結果與初始亂數、溫度及降溫參數有關，且比簡單爬山通常耗時較多。

**複雜度：** 若總共嘗試 `I` 次、每次完整計算路徑距離，時間約為 `O(I * n)`；路徑與最佳解的額外空間約 `O(n)`。

### 4. 梯度下降法：連續鬆弛版本

一般梯度下降法適用於可微分的連續變數，但 TSP 的答案是城市排列，屬於離散問題，所以不能直接對一條排列求一般意義的梯度。

本程式使用一個教學用的近似方式：

1. 建立矩陣 `W`，代表每個路徑位置選擇各城市的分數。
2. 對每一列套用 softmax，得到機率矩陣 `P`。`P[k][i]` 代表第 `k` 個位置選擇城市 `i` 的機率。
3. 目標函數包含預期巡迴距離，以及城市重複被選取時的懲罰項。
4. 計算目標函數對機率及分數矩陣的梯度，並更新 `W`。
5. 最後將機率矩陣解碼成一條每個城市恰好出現一次的合法路徑。

**特點與限制：** 這是將離散問題放寬成連續問題的教學實作。解碼後的路徑不一定是全域最佳解；結果也會受學習率、懲罰強度、迭代次數與初始值影響。

**複雜度：** 每次梯度更新需要計算位置、城市與相鄰城市的成本，約為 `O(n^3)`。若更新 `S` 步，總時間約為 `O(S * n^3)`；矩陣的空間使用量為 `O(n^2)`。

### 5. 貪婪演算法：最近鄰居法

從城市 0 開始，每一步都選擇與目前城市距離最近、且尚未造訪的城市，直到拜訪所有城市。

**特點：** 很快且容易理解，但每一步只考慮眼前的距離，不會預先考慮後面的路線，因此可能留下很長的最後一段路。它常用作其他改善演算法的初始解。

**複雜度：** 每一步最多掃描尚未拜訪的城市，總時間約為 `O(n^2)`；空間複雜度為 `O(n)`。

## 五、測試結果

在這份程式的固定測試資料（20 個城市，座標亂數種子為 42）上，一次測試結果如下：

| 方法 | 總路徑距離 | 觀察 |
|---|---:|---|
| 改良法（Greedy + 2-opt） | 352.32 | 本次測試中距離最短 |
| 爬山演算法 | 497.19 | 只接受較佳的交換，容易卡在局部最佳 |
| 模擬退火法 | 352.32 | 本次找到與改良法相同的路徑長度 |
| 梯度下降法（連續鬆弛） | 449.91 | 解碼後為合法巡迴路徑，但品質受近似與參數影響 |
| 貪婪演算法（最近鄰居） | 460.51 | 執行速度很快，但不會回頭改善路徑 |

執行時間會依電腦、Python 版本與系統負載不同而改變。隨機方法也可能因參數或亂數種子改變而得到不同結果。上表是本程式在指定設定下的一次結果，不代表每一種方法永遠會得到相同排名。

## 六、總比較

| 方法 | 是否隨機 | 接受較差解 | 主要優點 | 主要限制 |
|---|---|---|---|---|
| 改良法（2-opt） | 否 | 否 | 對貪婪初始路徑有明顯改善 | 可能停在 2-opt 局部最佳 |
| 爬山演算法 | 是 | 否 | 簡單、易實作 | 容易卡在局部最佳 |
| 模擬退火法 | 是 | 以機率接受 | 有機會跳出局部最佳 | 參數影響結果，運算較多 |
| 梯度下降法 | 初始化使用隨機值 | 透過連續近似更新 | 可以從連續最佳化角度嘗試處理 TSP | 必須鬆弛和解碼，不保證路徑品質 |
| 貪婪演算法 | 否 | 不適用 | 非常快，適合建立初始路徑 | 只看眼前選擇，整體路徑可能較差 |

## 七、結論

本作業用五種方法解決同一個 TSP，並使用相同的城市座標與距離函數比較路徑長度和執行時間。

貪婪演算法速度快，可以建立初始路徑；2-opt 改良法會主動檢查路徑中的可改善部分；爬山演算法只接受變好的鄰居，因此可能陷入局部最佳；模擬退火能依機率接受較差解，增加跳出局部最佳的機會；梯度下降則需要先把排列問題轉成連續機率形式，再將結果解碼成合法路徑。

這些方法都是啟發式或近似最佳化方法，通常能在合理時間內找到可用的路徑，但不保證找到全域最佳解。實驗也顯示，路徑品質與執行時間需要一起考量，不能只根據單次測試就認為某個方法在所有資料上都最好。
